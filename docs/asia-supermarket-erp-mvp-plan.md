# 亚洲食品超市进销存系统（MVP）方案 v0.1

## 1. 目标与原则
- **第一阶段目标（3-4个月）**：先打通“商品主数据 → 采购 → 入库 → 库存 → 销售出库 → 基础报表”的闭环。
- **业务原则**：
  - 一物多码（内/外包装、多供应商码、多条码）是核心能力，不做临时字段拼接。
  - 价格体系分层：基础价、会员价、活动价、合同价（供应商/会员定向）可叠加并有优先级。
  - 有效期/批次是食品业务主轴，所有库存按批次管理。
  - 仓库维度库存真实可追溯，网站端展示总库存但履约时按仓分配。

## 3. 核心数据模型（重点回答你的场景）

> 下面是“必须落库”的关键实体；MVP阶段建议用 PostgreSQL。

### 3.1 商品与条码
- `product`：
  - `id`
  - `name_en`（英文名）
  - `name_zh`（中文名）
  - `brand`
  - `spec`（规格，如 500g*24）
  - `category_lv1_id/category_lv2_id/category_lv3_id`（三级分类）
  - `shelf_life_days`（默认保质期天数）
  - `status`
- `product_identifier`（一物多标识）
  - `product_id`
  - `id_type`：`barcode_inner`/`barcode_outer`/`supplier_sku`/`legacy_code`
  - `id_value`
  - `supplier_id`（供应商编码可带供应商维度）
  - 唯一约束：`(id_type, id_value, supplier_id)`
- `product_packaging`
  - `product_id`
  - `pack_level`：`inner`/`outer`
  - `units_per_pack`
  - `barcode`
  - `list_price`

**意义**：支持“同商品不同条码、内外包装不同价格、不同供应商不同编码”。

### 3.2 会员与价格
- `member`
  - `id`, `mobile`, `tier`, `tag_json`
- `price_rule`
  - `rule_scope`：`member`/`member_group`
  - `match_type`：`exact_product`/`fuzzy_keyword`/`category`
  - `match_value`
  - `price_type`：`fixed_price`/`discount_rate`
  - `value`
  - `priority`
  - `valid_from/valid_to`
- `member_product_preference`
  - `member_id`, `product_id`
  - `repurchase_count_30d/90d`
  - `last_buy_at`
  - `preference_score`

**规则建议**：结算时价格优先级
`临时人工改价 > 指定会员商品价 > 会员组规则 > 活动价 > 常规零售价`。

### 3.3 采购与入库
- `purchase_order` / `purchase_order_line`
  - 支持按 `supplier_sku` 录入。
  - 若仅录“品牌+名称+规格”，调用匹配服务（模糊匹配+人工确认）。
  - 找不到时可一键“新建商品草稿”。
- `goods_receipt` / `goods_receipt_line`
  - 收货时录入：生产/到期日期、收货仓、批次号。
  - 自动计算联动字段：
    - 含税单价 ↔ 不含税单价（税率）
    - 行金额（含税/不含税）= 单价 × 数量

### 3.4 库存
- `stock_batch`
  - `warehouse_id`, `product_id`, `batch_no`, `expiry_date`, `qty_on_hand`, `qty_reserved`
- `stock_movement`
  - `movement_type`：`purchase_in`/`sale_out`/`adjust`/`transfer`
  - 形成可追溯台账。

网站库存展示逻辑：
- 前台显示 `sum(all_warehouse available_qty)`。
- 下单确认后执行“分仓分配策略”：
  1) 优先同城仓；
  2) 再选可满足整单的单仓；
  3) 再做拆单。
- 人工可覆盖自动分仓结果。

## 4. 关键业务流程设计

### 4.1 采购录单
1. 采购员输入供应商编码或“品牌+名称+规格”。
2. 系统自动匹配商品并回填分类、包装、税率、最近采购价。
3. 自动展示当前库存、近30天销量、最早有效期。
4. 输入本次数量后，自动联动税前税后金额。
5. 保存后进入审批（可选）并发给供应商。

### 4.2 收货入库
1. 按PO收货，支持部分到货。
2. 校验条码和包装层级（内/外箱自动换算最小单位）。
3. 录入有效期并生成批次库存。
4. 自动更新库存和采购成本。

### 4.3 会员结算与推荐
1. 扫会员 → 识别会员级别、标签、指定价规则。
2. 扫商品 → 执行价格引擎算最终价。
3. 交易完成后写入会员-商品行为，用于复购识别。
4. 推荐优先：
   - 高复购但近期未购买商品；
   - 同品类高偏好替代商品；
   - 临期可促销商品（对价格敏感会员）。

## 5. 你提到的“采购订单自动生成”建议算法（先规则后智能）

MVP先用可解释规则：

`建议订货量 = max(0, 预测需求 - 可用库存 + 安全库存)`

其中：
- `预测需求 = max(近7天销量*补货周期, 近30天日均*补货周期)`
- `可用库存 = 在库 - 已占用 + 在途`
- `安全库存 = 日均销量 * 安全天数`
- 对临期库存做折减（例如7天内过期不计入可用库存）

再加约束：
- 最小起订量（MOQ）
- 订货倍数（整箱）
- 预算上限
- 供应商到货周期（Lead Time）

输出“采购建议单”，采购员可一键转PO并手工修订。

## 6. 三张关键报表（可直接落地）

1. **临期商品核实表**
   - 字段：商品、批次、有效期、剩余天数、当前库存、近7天销量、预计售罄天数。
2. **特价商品核实表**
   - 字段：商品、原价、特价、活动起止、活动库存、活动期间销量。
3. **需关注商品表**
   - 规则：近期销量 < 前期销量或历史均值，且按当前速度无法在有效期前出清。
   - 增加建议动作：降价、捆绑、调仓、停止补货。

## 7. 技术实现建议（务实版）

- **后端**：NestJS / Spring Boot（二选一，按团队擅长）
- **数据库**：PostgreSQL（事务+复杂查询）
- **缓存**：Redis（价格规则、库存快照）
- **搜索/匹配**：PostgreSQL trigram 或 Elasticsearch（品牌+名称+规格模糊匹配）
- **前端**：管理后台（React + Ant Design）
- **集成**：POS、网站订单、打印机

### 性能与一致性要点
- 库存扣减用“事务 + 乐观锁版本号”。
- 价格引擎缓存并带失效策略（规则更新时间戳）。
- 所有出入库写流水，禁止直接改余额。

## 9. 风险与补强建议
- **主数据风险**：商品命名不统一导致重复建档。
  - 建议：建立“商品合并/别名”机制与主数据审核岗。
- **价格冲突风险**：多规则叠加混乱。
  - 建议：强制优先级与命中日志（可追溯为何此价）。
- **临期损耗风险**：有库存但不可售。
  - 建议：将“有效期可售天数”纳入补货算法。
