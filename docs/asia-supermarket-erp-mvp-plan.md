# 亚洲食品超市进销存系统（MVP）方案 v0.1

## 1. 目标与原则
- **第一阶段目标（3-4个月）**：先打通“商品主数据 → 采购 → 入库 → 库存 → 销售出库 → 基础报表”的闭环。
- **业务原则**：
  - 一物多码（内/外包装、多供应商码、多条码）是核心能力，不做临时字段拼接。
  - 价格体系分层：基础价、会员价、活动价、合同价（供应商/会员定向）可多重配置并有优先级，但**不折上折**。
  - 有效期管理以“最新进货有效期”为主；现场执行“近效期先出、分开存放”。系统不强制批次作业，降低操作复杂度。
  - 仓库维度库存真实可追溯，网站端展示总库存但履约时按仓分配。

## 2. 模块蓝图（按优先级）

### P0（必须先做）
1. **商品中心（Item Master）**
2. **会员与定价规则（Member & Pricing）**
3. **其它信息管理（Master Data）**：供应商（含订货周期）、员工（含店铺权限）
4. **促销管理（Promotion Management）**
5. **价签打印（Label Printing）**
6. **采购订单与收货入库（PO & GRN）**
7. **库存台账与仓间视图（Inventory Ledger）**
8. **报表中心（临期/特价/需关注）**

### P1（P0稳定后）
1. **采购建议单自动生成（Replenishment）**
2. **会员复购/偏好推荐（规则引擎 + 简易模型）**
3. **网站订单智能分仓（可人工覆盖）**

## 3. 核心数据模型（重点回答你的场景）

> 下面是“必须落库”的关键实体；MVP阶段建议用 PostgreSQL。

### 3.1 商品与条码
- `product`：
  - `id`
  - `name_en`（英文展示名，建议由品牌+名称/描述+规格组成）
  - `name_zh`（中文展示名，建议由品牌+名称/描述+规格组成）
  - `category_lv1_id/category_lv2_id/category_lv3_id`（三级分类）
  - `status`
- `product_supplier_sku`（供应商SKU列表）
  - `product_id`, `supplier_id`, `supplier_sku`, `status`（默认启用）
  - 唯一约束：`(supplier_id, supplier_sku)`
- `product_packaging`
  - `product_id`
  - `pack_level`：`inner`/`outer`
  - `units_per_pack`
  - `barcode`
  - `list_price`
  - `promo_price`, `promo_start_at`, `promo_end_at`

**意义**：支持“同商品不同条码、内外包装不同价格、不同供应商不同编码”。

### 3.2 会员与价格
- `member`
  - `id`, `mobile`, `tier`, `tag_json`
- `price_rule`
  - `rule_scope`：`member`/`member_group`
  - `match_type`：`exact_product`/`fuzzy_keyword`/`category`
  - `match_value`
  - `price_type`：`fixed_price`/`discount_rate`
  - `value`
  - `priority`
  - `valid_from/valid_to`
- `member_product_preference`
  - `member_id`, `product_id`
  - `repurchase_count_30d/90d`
  - `last_buy_at`
  - `preference_score`

**规则建议**：结算时价格优先级
`临时人工改价 > 指定会员商品价 > min(会员组规则价, 活动价) > 常规零售价`，其中会员组规则与活动价**取最低价，不叠加**。

### 3.3 采购与入库
- `purchase_order` / `purchase_order_line`
  - `purchase_order`（订单头）需包含：`warehouse_id`、`supplier_id`、`invoice_no`、`invoice_date`、`invoice_attachment_url`。
  - 支持按 `supplier_sku`、`product_id`、`barcode` 录入。
  - 若仅录“品牌+名称+规格”，调用匹配服务（模糊匹配+人工确认）。
  - 找不到时可一键“新建商品草稿”。
- `goods_receipt` / `goods_receipt_line`
  - `goods_receipt_line` 商品行仅需录入：到期日期（有效日期）。
  - 收货录入时，每个商品行提示：当前库存数量、有效日期、平均进价、上次进价、毛利率。
  - 根据当前售价与本次进价自动计算“本次毛利率”，超出阈值（如低于5%或高于60%）高亮提醒。
  - 自动计算联动字段：
    - 含税单价 ↔ 不含税单价（税率）
    - 行金额（含税/不含税）= 单价 × 数量
    - 支持 `outer/carton数`、`inner数`、`商品数` 任一录入并联动；以商品数为基准。
    - 未定义 `inner` 包装数量默认 1；未定义 `outer` 包装数量默认等于 `inner` 包装数量。

### 3.4 库存
- `stock_balance`
  - `warehouse_id`, `product_id`, `qty_on_hand`, `qty_reserved`, `latest_expiry_date`
- `stock_movement`
  - 关键字段：`warehouse_id`, `product_id`, `movement_date`, `movement_type`, `quantity`
  - `movement_type`：`purchase_in`/`sale_out`/`adjust`/`transfer`
  - 形成可追溯台账。

网站库存展示逻辑：
- 前台显示 `sum(all_warehouse available_qty)`。
- 下单确认后执行“分仓分配策略”：
  1) 优先同城仓；
  2) 再选可满足整单的单仓；
  3) 再做拆单。
- 人工可覆盖自动分仓结果。

### 3.5 促销管理
- `promotion_campaign`
  - `id`, `name`, `campaign_type`（单品特价/分类折扣/会员定向）, `start_at`, `end_at`, `status`
  - `apply_scope`（商品/分类/品牌）, `stackable`（默认否）
- `promotion_item`
  - `campaign_id`, `product_id`, `pack_level`, `promo_price` / `discount_rate`

适用场景：支持对某一类、某一系列中的某些商品，或单个商品设置折扣或一口价。

### 3.6 价签打印
- `label_print_task`
  - `id`, `task_type`（普通正价签/特价促销签/补打）, `template_id`, `created_by`, `printed_at`
- `label_print_line`
  - `task_id`, `product_id`, `pack_level`, `price_to_print`, `copies`

规则：
- 新建商品后自动加入普通正价签打印列表。
- 补打价签可通过条码、供应商SKU加入打印列表。
- 促销商品配置完成后自动加入特价促销签打印列表（彩色打印纸）。
- 打印规格：A4，每页七行三列。

## 4. 关键业务流程设计

### 4.1 采购录单
1. 采购员输入供应商编码或“品牌+名称+规格”。
2. 系统自动匹配商品并回填分类、包装、税率、最近采购价。
3. 自动展示当前库存、近30天销量、最早有效期。
4. 输入本次数量后，自动联动税前税后金额。
5. 保存后进入审批（可选）并发给供应商。

### 4.1.1 促销管理流程（新增）
1. 运营创建促销活动（类型、时间窗、适用商品/分类、会员范围）。
2. 系统做规则冲突检查（是否与现有活动重叠、是否违反“不折上折”）。
3. 活动审核通过后生效，并生成“待打印价签清单”。
4. 到期自动失效并回切原价/规则价。

### 4.1.2 价签打印流程（新增）
1. 门店按“促销生效/价格变更/补打”生成打印任务。
2. 选择模板（中文/双语、是否含条码、是否含促销起止）。
3. 预览并打印；打印后记录任务与明细，支持补打与作废重打。
4. 店员执行上架替换并可勾选“已更换”形成闭环。

### 4.2 收货入库
1. 按供应商 invoice 收货，支持上传 PDF/JPG 等凭证；以实收为准，不做部分到货。
2. 条码与包装层级以人工核验为主，系统做数量联动辅助。
3. 录入有效期并更新商品最新有效日期（不做批次库存作业）。
4. 自动更新库存和采购成本。

### 4.3 会员结算与推荐
1. 扫会员（支持手机号/生日）→ 识别会员级别、标签、指定价规则；生日当天可自动触发生日优惠。
2. 扫商品 → 执行价格引擎算最终价。
3. 交易完成后写入会员-商品行为，用于复购识别。
4. 推荐优先：
   - 高复购但近期未购买商品；
   - 同品类高偏好替代商品；
   - 临期可促销商品（对价格敏感会员）。

## 5. 你提到的“采购订单自动生成”建议算法（先规则后智能）

生成建议单时，建议展示字段：
- 商品、单箱数量、在库、占用、在途、可用库存、安全库存
- 近30日日均销量、连续30日最大销量（日均口径）、预测需求
- 最小订货量、上次订货量、建议订货量

说明：供应商在采购建议单“订单头”层面选择，不在商品字段重复展示。

MVP先用可解释规则：

`最小订货量 = max(0, 预测需求 - 可用库存 + 安全库存)`

`建议订货量 = max(最小订货量, 上次订货量)`

其中：
- `补货周期 = 订货周期（供应商维度维护）`
- `预测需求 = max(近30天日均销量*补货周期, 连续30天最大销量(日均)*补货周期)`
- `可用库存 = 在库 - 已占用 + 在途`
- `安全库存 = 日均销量 * 安全天数（建议默认7天）`
- 对临期库存做折减（例如7天内过期不计入可用库存）

再加约束：
- 最小起订量（MOQ）
- 订货倍数（整箱）
- 预算上限
- 供应商到货周期（Lead Time）

输出“采购建议单”，采购员可一键转PO并手工修订。

## 6. 三张关键报表（可直接落地）

1. **临期商品核实表**
   - 字段：商品代码、商品名称、有效期、剩余天数、当前库存、近7天销量、上次进货日期、上次进货数量、预计售罄天数。
   - 查询：按商品代码（可查看商品详情含供应商）、商品类别、商品名模糊、剩余天数（7/30/60）筛选。
   - 排序：支持按库存数量、剩余天数排序。
   - 输出：支持“打印第一页（重点商品）”用于现场核对。
2. **特价商品核实表**
   - 字段：商品、原价、特价、含税进价、活动起止、当前库存、最近7日销量。
   - 查询：按商品类别、商品名模糊筛选。
   - 排序：支持按名称、库存数量排序。
   - 输出：支持“打印第一页”用于某类/某系列商品现场核对。
3. **需关注商品表**
   - 规则：近期销量 < 前期销量或历史均值，且按当前速度无法在有效期前出清。
   - 增加建议动作：降价、捆绑、调仓、停止补货。

## 7. 技术实现建议（务实版）

- **后端**：NestJS / Spring Boot（二选一，按团队擅长）
- **数据库**：PostgreSQL（事务+复杂查询）
- **缓存**：Redis（价格规则、库存快照）
- **搜索/匹配**：PostgreSQL trigram 或 Elasticsearch（品牌+名称+规格模糊匹配）
- **前端**：管理后台（React + Ant Design）
- **集成**：POS、网站订单、打印机

### 性能与一致性要点
- 库存扣减用“事务 + 乐观锁版本号”。
- 价格引擎缓存并带失效策略（规则更新时间戳）。
- 所有出入库写流水，禁止直接改余额。

## 9. 风险与补强建议
- **主数据风险**：商品命名不统一导致重复建档。
  - 建议：建立“商品合并/别名”机制与主数据审核岗。
- **价格冲突风险**：多规则叠加混乱。
  - 建议：强制优先级与命中日志（可追溯为何此价）。
- **临期损耗风险**：有库存但不可售。
  - 建议：将“有效期可售天数”纳入补货算法。

## 11. 现有模块细化（实施清单）

### 11.1 商品中心（细化）
- 必填校验：`name_zh/name_en`、三级分类、至少一个包装定义。
- 约束：同商品下 `pack_level` 不可重复；条码全局唯一。
- 搜索：支持中文名模糊、英文名模糊、条码精确、供应商SKU精确。

### 11.2 采购与收货（细化）
- 订单头：仓库、供应商、发票号、发票日期、附件。
- 订单行：商品、包装层级、数量（outer/inner/unit联动）、税率、税前税后单价与金额。
- 收货后自动动作：更新库存、更新商品最新有效日期、更新最近采购价。

### 11.3 价格与促销（细化）
- 生效检查：活动时间不可反向、活动商品不可为空。
- 冲突检查：同商品同时间窗多个活动时，按优先级+最低价规则决策。
- 审计：记录每次价变的来源（人工改价/活动/会员规则）。

### 11.4 价签打印（细化）
- 模板字段建议：商品名、规格、条码、现价、原价（促销时）。
- 价签分两类：普通正价签、特价促销签（彩色打印纸）。
- 打印后清空任务列表；门店按打印结果立即替换。

### 11.5 报表（细化）
- 报表按人工“打开并查询”实时生成，不做定时刷新任务。
- 导出：支持 Excel 与打印视图。
- 权限：采购可看全仓，门店仅看本店关联仓。

### 11.6 其它信息管理（细化）
- 供应商：名称、结算方式、订货周期（天）、默认到货仓、启用状态。
- 员工：姓名、账号、所属门店、可访问门店列表、角色（店员/店长/采购/管理员）。
- 权限：按“角色 + 店铺”双维度控制，敏感操作（改价/库存调整）强制留痕。
